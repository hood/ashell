ashell is a shell prompt backed by a tiny per-user daemon. Performance is a first class citizen here, so frame 1 lands in ~115 µs, slow stuff like git status patches in as it finishes, and nothing on the critical path ever spawns a process, even in a 23k-file repo.

// benchmarks

Faster than forking /usr/bin/true.

On macOS, a bare fork+exec costs ~4 ms before any work happens. Every prompt that shells out pays that. ashell's zsh side never forks: it talks to the daemon with zsh/net/socket and sysread, so the whole round trip is cheaper than spawning nothing.

// how it works

Draw now. Patch later.

Most prompts block on their slowest module. ashell splits rendering in two: an instant frame from whatever is cached, then patch frames pushed over the socket as slow segments finish. zsh repaints via zle -F + reset-prompt, so you can start typing right away.

A daemon that remembers

One per user. Keeps parsed config, directory listings, git state and toolchain versions in memory across prompts and shells. A filesystem watcher (FSEvents / inotify) marks exactly what changed, so the next status only looks at that.

Zero-fork shell side

Pure zsh: zsocket, sysread, syswrite, zle -Fw. Frames are 0x1F/0x1E-delimited, one syscall each way, no JSON. Prompt text goes through a variable with prompt_subst, so a branch named $(rm -rf ~) is just text.

// git status

Git status in O(what changed).

Native status on top of gitoxide plus an in-memory untracked cache. The watcher's dirty set means an edit re-checks one file, not 23k. Staged changes walk git's own cache-tree, which is valid right after a commit. When cold, git answers while the native cache warms in the background.

// toolchains

Versions without the spawn tax.

Detected like starship (marker files, extensions). The version is keyed on the resolved binary's stat, pin files up the tree, global defaults and env. The tool only runs again when that key changes, on a 4-thread pool, never on the render path.

🦀 rust⬢ node🐍 python + venv🐹 go💎 ruby☕ java🥟 bun🦕 deno

⚡One-shot fallback

No daemon? The same core renders in-process and spawns the daemon detached. Next prompt is back to microseconds.

↻Self-upgrading

The daemon exits when its binary changes. Rebuild, hit enter, you're on the new version.

◐Stale, not wrong

Cached values render dimmed while they revalidate. You always know what's fresh.

?ashell explain

Per-segment timings, cold vs warm, p50/p99, and how long the async git status took.

🔒Locked down

Socket in a 0700 dir, peer uid checked. The daemon never trusts its own env: the shell sends the vars segments depend on.

≋Survives everything

Daemon killed mid-session, SIGPIPE, dropped watcher events: falls back cleanly, reconnects on the next prompt.

// config

Powerline in twenty lines.

One TOML file at ~/.config/ashell/config.toml. Every key optional, Starship-like styles (bold cyan, bg:#1e1e2e, fg:208). Typos are errors with line numbers, and a broken file falls back to defaults with a ⚠ config marker instead of a dead prompt.

// install

    
Two lines. Done.

  

  

    
Build it
Needs Rust 1.88+ (rustup update if rustc --version is older). Release profile is fat LTO, single codegen unit, panic = "abort".
cargo install --locked --git https://github.com/hood/ashell

    
Hook it into zsh
Add to ~/.zshrc. The daemon starts itself on the first prompt.
eval "$(ashell init zsh)"

    
Make it yours (optional)
Dump the documented defaults, edit, then ashell stop to reload.
ashell config default > ~/.config/ashell/config.toml
ashell config check
ashell stop
